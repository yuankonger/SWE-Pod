## 1. Which well-known systems use hand-fixed roles and team size, and what do their own ablations say?

### Takeaway
MetaGPT, ChatDev, CAMEL-style pairs, AutoGen group chats, CrewAI crews and Magentic-One all have the roster and role prompts written by a human; the model at most picks the next speaker or assigns tasks within that roster. Their own ablations mostly show that removing a hand-written role hurts (ChatDev executability 0.88 to 0.58; Magentic-One minus 21% to 39% per agent removed), but these are ablations of the authors' own design on small samples, not comparisons against a model-chosen structure, and several show non-monotonic or negative effects of adding agents.

### Cited Findings

**MetaGPT (Hong et al., ICLR 2024; arXiv Aug 2023). Read via ar5iv full text.**
- Five hand-defined roles (Product Manager, Architect, Project Manager, Engineer, QA Engineer), each with a hand-written profile, in a fixed sequential SOP copied from human software-company practice; no automatic choice of roles or team size, and dynamic collaboration is listed as future work — [MetaGPT, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.00352)
- Role ablation (Table 3), columns = roles present / #agents / lines of code / expense / human revisions / executability: Engineer only: 1 / 83.0 / $0.915 / 10 / 1.0. + Product Manager: 2 / 112.0 / $1.059 / 6.5 / 2.0. + Architect: 3 / 143.0 / $1.204 / 4.0 / 2.5. Engineer + Product + Project Manager: 3 / 205.0 / $1.251 / 3.5 / 2.0. All four: 4 / 191.0 / $1.385 / 2.5 / 4.0 — [MetaGPT, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.00352)
- The ablation is not monotonic in executability (the three-agent variant with Project Manager scores 2.0, below the three-agent variant with Architect at 2.5), and the QA Engineer role is not ablated — [MetaGPT, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.00352)
- MetaGPT versus ChatDev on SoftwareDev (MetaGPT's own Table 1): executability 3.75 versus 2.25; tokens 31,255 versus 19,292; human revision cost 0.83 versus 2.5 — [MetaGPT, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.00352)

**ChatDev (Qian et al., ACL 2024; arXiv Jul 2023). Read via ar5iv full text.**
- Fixed "chat chain" of design, coding (writing, completion) and testing (review, system test) phases; each subtask pairs an instructor and an assistant whose roles (CEO, CTO, programmer, reviewer, tester) are set by system prompt; phase order is predetermined — [ChatDev, ar5iv](https://ar5iv.labs.arxiv.org/html/2307.07924)
- Removing the role assignments from system prompts (Table 4): Completeness 0.5600 to 0.5400, Executability 0.8800 to 0.5800, Consistency 0.8021 to 0.7385, Quality 0.3953 to 0.2212; the largest drop of any ablated component — [ChatDev, ar5iv](https://ar5iv.labs.arxiv.org/html/2307.07924)
- ChatDev's own comparison reverses MetaGPT's: GPT-Engineer 0.1419, MetaGPT 0.1523, ChatDev 0.3953 on Quality; Executability 0.3583 / 0.4145 / 0.8800 — [ChatDev, ar5iv](https://ar5iv.labs.arxiv.org/html/2307.07924); contradicted in direction by [MetaGPT's Table 1](https://ar5iv.labs.arxiv.org/html/2308.00352) (each paper's own benchmark and metric favours its own system)

**AgentVerse (Chen et al., ICLR 2024; arXiv Aug 2023; PDF marked "Preprint", v3 Oct 2023). Read in full text.** Roles are model-chosen but team size is hand-fixed, so it belongs partly here.
- "Currently the number of experts is pre-defined by us for each task": four agents for dialogue, code completion and constrained generation; two for mathematical reasoning; two or three for tool use — [AgentVerse PDF](https://arxiv.org/pdf/2308.10848)
- The authors cut the maths team to two because "an increase in the number of reviewers for mathematical reasoning tasks correlates with a higher likelihood of them giving erroneous critiques, leading to incorrect solutions by the solver" — [AgentVerse PDF](https://arxiv.org/pdf/2308.10848)
- Table 1 (CoT / Solo / Group). GPT-3.5-Turbo: FED 81.6 / 81.1 / 85.1; Commongen-Challenge 76.6 / 93.6 / 92.3; MGSM 80.4 / 82.4 / 80.8. GPT-4: FED 95.4 / 95.8 / 96.8; Commongen 95.9 / 99.0 / 99.1; MGSM 95.2 / 96.0 / 95.2; Logic Grid Puzzles 59.5 / 64.0 / 66.5. The authors note that for GPT-3.5-Turbo "the Group setup underperforms the Solo setup in two of three tasks" — [AgentVerse PDF](https://arxiv.org/pdf/2308.10848)

**Magentic-One (Fourney et al., Microsoft Research, arXiv 7 Nov 2024; preprint / vendor research). Read in full text.**
- Hand-fixed team: Orchestrator plus WebSurfer, FileSurfer, Coder, ComputerTerminal. The Orchestrator (model) writes a task ledger (facts, guesses, plan) and a progress ledger, picks which agent acts next, detects stalls, re-plans and decides task completion. It does not create or remove agents — [Magentic-One PDF](https://arxiv.org/pdf/2411.04468)
- Results: 38% on GAIA, 32.8% on WebArena, 27.7% on AssistantBench (GAIA test 32.33±5.3 with GPT-4o; 38.00±5.5 with GPT-4o + o1) — [Magentic-One PDF](https://arxiv.org/pdf/2411.04468)
- Ablations on the GAIA validation set: replacing the ledger-based Orchestrator with AutoGen's GroupChat-style "decide who speaks next" orchestrator drops performance by 31%; "removing any single agent reduces performance by between 21% (Coder, Executor) to 39% (FileSurfer)" — [Magentic-One PDF](https://arxiv.org/pdf/2411.04468)
- Qualitative note: with an agent removed, remaining agents sometimes "compensated for missing capabilities in creative ways" (for example FileSurfer reading code and predicting its output when Coder and Terminal were absent) — [Magentic-One PDF](https://arxiv.org/pdf/2411.04468)

**AutoGen group chat defaults (vendor documentation).**
- In `SelectorGroupChat` the developer passes a fixed participant list; a model selects the next speaker from participant names and descriptions; termination is a developer-set condition (for example a "TERMINATE" mention or `max_messages=25`). It is described as "similar to RoundRobinGroupChat, but with a model-based next speaker selection mechanism" — [AutoGen docs](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html)

**CrewAI (vendor documentation).**
- The developer defines agents and tasks and chooses a process. Sequential: tasks run in listed order. Hierarchical: a manager LLM or manager agent plans, delegates and validates; "Tasks are not pre-assigned" — [CrewAI docs](https://docs.crewai.com/en/concepts/processes)

**ChatEval (Chan et al., arXiv Aug 2023; preprint as read). Read via ar5iv.** Hand-fixed evaluator personas.
- Accuracy on FairEval rose with number of roles, peaking at 62.5% with 3 and 4 roles, then dropped at 5; adding discussion turns showed no clear upward trend and often stalled or degraded — [ChatEval, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.07201)

### Inferences
- "Fixed" comes in two grades: fully scripted pipelines (MetaGPT, ChatDev, CrewAI sequential) and fixed roster with model-chosen turn-taking (AutoGen selector chat, Magentic-One, CrewAI hierarchical). The second grade already delegates "who acts next" and "when to stop" to the model, so the fixed/self-organised axis is a spectrum, not a binary.
- Role-removal ablations show that a system tuned with a role degrades when that role is deleted. They do not show that the hand-chosen roster is better than one the model would have chosen, and the MetaGPT/ChatDev cross-claims show how benchmark- and metric-dependent such results are.
- Even hand-fixed systems report "more agents hurt" cases (AgentVerse maths reviewers, ChatEval at 5 roles, GPT-3.5 Group below Solo).

### Gaps
- CAMEL: I did not fetch the paper; no ablation on team size is recorded here. CAMEL's fixed two-role (AI user / AI assistant) design is described only second-hand in the other papers read.
- MetaGPT's ablation uses a small task subset; sample sizes and variance were not reported in the text I read.
- No ablation found for AutoGen or CrewAI defaults from the vendors themselves.

## 2. Which systems let structure be decided automatically, and what exactly does the model decide?

### Takeaway
There are three distinct families: (i) offline search that produces one fixed structure per task domain (ADAS, AFlow, GPTSwarm, MASS, AgentSquare); (ii) per-query generation or selection before execution (MaAS, G-Designer, ScoreFlow, FlowReasoner, MAS-GPT, MAS-Orchestra, DyLAN, AutoAgents); and (iii) run-time orchestrators that spawn or re-form teams during execution (Captain Agent, AOrchestra, Anthropic's research system, Claude Code agent teams, managed Devins). Only family (iii), plus a few of family (ii), lets the model choose the number of agents; many "automatic" systems still fix the agent count or the candidate pool by hand.

### Cited Findings

**Survey framing (preprint).**
- Yue et al., "From Static Templates to Dynamic Runtime Graphs" (arXiv 23 Mar 2026) classifies methods by graph determination time (offline, pre-execution, in-execution) and graph plasticity (none, select, generate, edit). Static/offline: AFlow, ADAS, MASS and others. Dynamic select: DyLAN, AgentDropout, MasRouter. Dynamic pre-execution generate: G-Designer, MaAS, ScoreFlow, FlowReasoner. Hybrid: AutoAgents. In-execution edit: AOrchestra, DyFlow, ProAgent, EvoFlow and others — [Yue et al. 2026](https://arxiv.org/html/2603.22386v1)

**Family (i): offline search, structure then fixed per domain.**
- ADAS / Meta Agent Search (Hu, Lu, Clune; ICLR 2025): a meta agent writes new agents in code, with an archive; searches prompts, tool use, workflows; one search per domain — [ADAS PDF](https://arxiv.org/pdf/2408.08435)
- AFlow (Zhang et al.; ICLR 2025): Monte Carlo Tree Search over code-represented workflows with predefined operators — [AFlow PDF](https://arxiv.org/pdf/2410.10762)
- GPTSwarm (Zhuge et al.; ICML 2024): agents as computational graphs; optimises node prompts and edge connectivity — [GPTSwarm abstract](https://arxiv.org/abs/2402.16823) (abstract only; no numbers in abstract)
- MASS (Zhou et al., Google; arXiv Feb 2025, v2 Jan 2026): interleaves block-level prompt optimisation, topology search in a pruned space, then workflow-level prompt optimisation — [MASS](https://arxiv.org/html/2502.02533)
- AgentSquare (Shang et al.; arXiv Oct 2024, preprint as listed): searches a modular single-agent design space (Planning, Reasoning, Tool Use, Memory); claims "average performance gain of 17.2% against best-known human designs" on six benchmarks — [AgentSquare abstract](https://arxiv.org/abs/2410.06153) (abstract only)
- EvoAgent (Yuan et al.; NAACL 2025): evolutionary operators (mutation, crossover, selection) extend one specialised agent into a multi-agent system — [EvoAgent abstract](https://arxiv.org/abs/2406.14228) (abstract only; no numbers)
- EvoMAC (Hu et al.; arXiv Oct 2024, preprint as listed): "textual backpropagation" updates the collaboration network from test feedback for software development — [EvoMAC abstract](https://arxiv.org/abs/2410.16946) (abstract only; no numbers)

**Family (ii): per-query selection or generation before execution.**
- DyLAN (Liu et al.; COLM 2024): two stages. Team optimisation selects a subset of candidate agents using an unsupervised Agent Importance Score from a preliminary trial; task solving uses a dynamic feed-forward communication structure with early stopping. Decided automatically: which agents (from a hand-written candidate pool), who talks to whom per layer, when to stop — [DyLAN PDF](https://arxiv.org/pdf/2310.02170)
- AutoAgents (Chen et al.; IJCAI 2024): generates the required expert agents from the task content, plans with them, and an observer role critiques the plan and agents — [AutoAgents abstract](https://arxiv.org/abs/2309.17288) (abstract only; no numbers)
- AgentVerse recruitment: a "recruiter" agent writes the expert descriptions per task and can adjust composition from evaluation feedback; the count `${cnt_critic_agents}` is supplied by the experimenter — [AgentVerse PDF](https://arxiv.org/pdf/2308.10848)
- G-Designer (Zhang et al.; arXiv Oct 2024, preprint as listed): a graph neural network generates a task-specific communication topology — [G-Designer abstract](https://arxiv.org/abs/2410.11782) (abstract only)
- MaAS (Zhang et al.; arXiv Feb 2025, preprint as listed): samples a query-dependent architecture from a probabilistic "agentic supernet" — [MaAS abstract](https://arxiv.org/abs/2502.04180) (abstract only)
- ScoreFlow (Wang et al.; arXiv Feb 2025, preprint): score-based preference optimisation for workflow generation; "8.2% improvement over existing baselines" on six benchmarks — [ScoreFlow abstract](https://arxiv.org/abs/2502.04306) (abstract only)
- FlowReasoner (Gao et al.; arXiv Apr 2025, preprint): a reasoning meta-agent, trained with RL on execution feedback, generates "a personalized multi-agent system for each user query"; surpasses o1-mini by 10.52% accuracy across three benchmarks — [FlowReasoner abstract](https://arxiv.org/abs/2504.15257) (abstract only)
- MAS-GPT (Ye et al.; arXiv Mar 2025, preprint): a fine-tuned 32B model emits a complete query-specific multi-agent system as executable code in one inference (agents as variables, LLM calls as functions); case studies show five-agent systems and four parallel pipelines chosen by the model — [MAS-GPT PDF](https://arxiv.org/pdf/2503.03686)
- MAS-Orchestra (Ke et al., Salesforce; arXiv Jan 2026, v5 May 2026, preprint): an RL-trained orchestrator generates the whole system in one step with `create_agent` and `create_flow`; sub-agents are black-box callable functions (CoT, SC, Debate, Reflexion and similar). "Low degree of MAS" allows at most one sub-agent; "high" leaves the number unconstrained — [MAS-Orchestra](https://arxiv.org/html/2601.14652)
- AgentNet (Yang et al.; arXiv Apr 2025, preprint): no central orchestrator; agents adjust connectivity and route tasks in a dynamic DAG and specialise via retrieval memory — [AgentNet abstract](https://arxiv.org/abs/2504.00587) (abstract only; no numbers)

**Family (iii): run-time orchestrator decides.**
- Captain Agent (Song et al., AutoGen group; arXiv May 2024, v3 Mar 2025, preprint): the captain decomposes the task, proposes roles per subtask, retrieves or generates agents and tools, runs a nested group chat, reads a reflector's report, then "either adjusts the team composition or the subtask instructions and repeats the cycle or concludes the task". Decided by the model: roles, number of agents per subtask, tools, when to rebuild, when to stop. The agent library held 541 agents after all experiments — [Captain Agent PDF](https://arxiv.org/pdf/2405.19425)
- AOrchestra (Ruan et al.; arXiv Feb 2026, preprint): models any agent as the tuple (Instruction, Context, Tools, Model); the orchestrator fills the tuple and creates a sub-agent on the fly at each step; reports a 16.28% relative improvement over the strongest baseline with Gemini-3-Flash across GAIA, SWE-Bench and Terminal-Bench — [AOrchestra abstract](https://arxiv.org/abs/2602.03786) (abstract only)
- Anthropic multi-agent research system (vendor blog, 13 Jun 2025): the lead agent plans, spawns subagents in parallel, then "decides whether more research is needed" and can create more. Prompted effort-scaling rules: simple fact-finding 1 agent with 3–10 tool calls; direct comparisons 2–4 subagents with 10–15 calls each; complex research more than 10 subagents with divided responsibilities — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code agent teams (vendor documentation, experimental, off by default): "Claude decides the number of teammates to spawn based on your task, or you can specify exactly what you want". Lead creates tasks; teammates self-claim unblocked tasks and "message each other directly"; no nested teams; lead is fixed. With subagents instead, "Main agent manages all work" and results return to the caller — [Claude Code docs](https://code.claude.com/docs/en/agent-teams)
- OpenAI Agents SDK (vendor documentation): the developer defines each agent's instructions, tools and handoffs. "Orchestrating via LLM" lets the model choose tools and handoffs at run time; "orchestrating via code" fixes the flow and is "more deterministic and predictable" in speed, cost and performance. Two patterns: agents-as-tools (manager keeps control) and handoffs (triage routes to a specialist) — [OpenAI Agents SDK docs](https://openai.github.io/openai-agents-python/multi_agent/)
- Managed Devins (vendor blog, 19 Mar 2026): the main Devin session acts as coordinator, splits work and hands it to child sessions, each a full Devin in its own VM; the coordinator can message, pause or stop children — [Cognition blog](https://cognition.ai/blog/devin-can-now-manage-devins) (via search summary)
- Cursor long-running agents (vendor blog, 14 Jan 2026): planners explore and create tasks and "can spawn sub-planners"; workers execute without coordinating with each other; a judge decides at the end of each cycle whether to continue. Roles are prescribed by Cursor; the number of sub-planners and tasks is model-decided — [Cursor blog](https://cursor.com/blog/scaling-agents)
- Anthropic C-compiler experiment (vendor blog, 5 Feb 2026): 16 parallel Claude agents with no orchestrator ("I don't use an orchestration agent"); agents claim tasks by writing lock files in `current_tasks/`, synchronised through git; the human assigned some specialised roles (deduplication, performance, code-quality critique, documentation). About 2,000 sessions, roughly 2 billion input and 140 million output tokens, just under $20,000, yielding a roughly 100,000-line compiler that builds Linux 6.9 — [Anthropic engineering blog](https://www.anthropic.com/engineering/building-c-compiler)

### Inferences
- Much of the "automatic design" literature moves the human choice up one level: the designer no longer fixes the team but fixes the operator library, the candidate agent pool, the sub-agent catalogue or the search space. G-Designer and DyLAN, for example, do not choose how many candidate agents exist.
- Vendor systems converge on hub-and-spoke orchestrator-worker designs in which the model chooses the count and briefs of workers, with the count guided by explicit prompt heuristics rather than left wholly free.

### Gaps
- Google ADK and A2A: the ADK documentation page redirected and returned no content; no primary description was captured. I found no reliable source in this pass for how ADK splits developer-fixed workflow agents from model-driven transfer.
- OpenAI Swarm (the earlier experimental library) was not separately fetched; only the successor Agents SDK documentation is cited.
- G-Designer, MaAS, GPTSwarm, AutoAgents, EvoAgent, EvoMAC, AgentNet, ScoreFlow, FlowReasoner, AgentSquare: abstract only, so exactly which of count, roles and stopping each one fixes is not confirmed from full text.
- Cognition's April 2026 follow-up essay on what is working in multi-agent systems was seen only through a third-party (ZenML) summary; the original was not located.

## 3. Does model-chosen structure beat fixed structure? Head-to-head numbers, task types and cost

### Takeaway
Papers proposing automatic design report gains of roughly 3 to 20 points over hand-designed baselines, but independent or later re-evaluations repeatedly find that the gains shrink or reverse against strong simple baselines (CoT with self-consistency, single-agent execution of the same workflow, prompt optimisation), and one 2026 study finds expert-designed systems beating automatic ones on both accuracy and cost. The evidence is conflicting and almost entirely on short reasoning, QA and code-snippet benchmarks; there is very little controlled head-to-head evidence on long-horizon software engineering.

### Cited Findings

**Evidence favouring automatic or adaptive structure (authors' own evaluations).**
- ADAS (ICLR 2025), GPT-3.5 execution, Table 1 (Reading Comprehension F1 on DROP / Math MGSM / Multi-task MMLU / Science GPQA): CoT 64.2 / 28.0 / 65.4 / 29.2; CoT-SC 64.4 / 28.2 / 65.9 / 30.5; LLM Debate 60.6 / 39.0 / 65.6 / 31.4; Role Assignment 65.8 / 30.1 / 64.5 / 31.1; Meta Agent Search 79.4 / 53.4 / 69.6 / 34.6. Headline: +13.6 F1 on DROP and +14.4% on MGSM; +25.9% on GSM8K and +13.2% on GSM-Hard under transfer. The gap is small on Multi-task and Science. One search run costs about $500 (ARC) or about $300 (other domains) — [ADAS PDF](https://arxiv.org/pdf/2408.08435)
- AFlow (ICLR 2025), GPT-4o-mini, Table 1 averages over HotpotQA, DROP, HumanEval, MBPP, GSM8K, MATH: IO 72.8; CoT 74.7; CoT-SC (5-shot) 76.0; MedPrompt 75.3; MultiPersona 75.1; Self-Refine 70.7; ADAS 67.2; AFlow 80.3. Stated as 5.7% over manually designed methods and 19.5% over existing automated approaches; smaller models reach GPT-4o parity "at 4.55% of its inference cost" — [AFlow PDF](https://arxiv.org/pdf/2410.10762)
- AFlow also notes a workflow found with DeepSeek-V2.5 "performs notably weaker on GPT-4o-mini" than one found with GPT-4o-mini, i.e. "different language models require different workflows" — [AFlow PDF](https://arxiv.org/pdf/2410.10762)
- DyLAN (COLM 2024), GPT-3.5: HumanEval Pass@1 single 73.2 (1.00 API calls), CAMEL 69.5 (12.03), AgentVerse 75.0 (22.50), LATS 81.1 (48.00), DyLAN 82.9 (16.85). WebShop reward: direct 50.6, ReAct 53.8, Reflexion 62.0, BOLAA 66.0, DyLAN 68.3 (24.85 calls). Versus LLM Debate: +10.2% accuracy with 10.6% fewer API calls on one benchmark, and better performance at 36.6% of Debate's calls on another — [DyLAN PDF](https://arxiv.org/pdf/2310.02170)
- DyLAN team optimisation: selecting agents improves accuracy "up to 25.0%" on specific MMLU subjects and overall "up to 6.7%" with lower cost; "DyLAN with an optimized team of 3 agents can outperform both DyLAN before team optimization and LLM Debate with 4 agents" — [DyLAN PDF](https://arxiv.org/pdf/2310.02170)
- Captain Agent (preprint): "21.94% improvement on average accuracy" over existing multi-agent methods across six scenarios. Static versus adaptive ablation: team built once at round 1 versus re-formed across rounds; adaptive beats static in four of five scenarios and matches in one in the introduction's wording, while the ablation section says adaptive wins "except in (Sci) Physics"; on data analysis adaptive is ahead "by over 30.43% on accuracy". Cost: with the same backbone Captain Agent achieves "the best performance but also the highest cost" — [Captain Agent PDF](https://arxiv.org/pdf/2405.19425)
- MaAS (preprint): "requires only 6% to 45% of the inference costs" of handcrafted or automated systems and surpasses them by 0.54% to 11.82% across six benchmarks — [MaAS abstract](https://arxiv.org/abs/2502.04180) (abstract only)
- G-Designer (preprint): 84.50% on MMLU, 89.90% pass@1 on HumanEval, token reduction "up to 95.33% on HumanEval", 0.3% accuracy drop under agent adversarial attack — [G-Designer abstract](https://arxiv.org/abs/2410.11782) (abstract only)
- MAS-GPT (preprint), Llama-3-70B driving the systems, 10 baselines on 8 benchmarks: beats the second-best method by 3.89% on average and the single LLM by 13.34%; beats MATH-optimised AFlow on MATH by 3.53% while AFlow's MATH workflow fails to generalise out of domain; fewest inference calls of the four methods in its cost figure — [MAS-GPT PDF](https://arxiv.org/pdf/2503.03686)
- MAS-Orchestra (preprint), Avg@8 accuracy on AIME24 / AIME25 / HotpotQA / BrowseComp+ / GPQA: CoT agent 50.00 / 45.00 / 33.56 / 1.12 / 60.54; SC agent 57.50 / 51.67 / 35.50 / 0.75 / 62.88; Debate agent 62.08 / 57.50 / 36.88 / 0.81 / 64.14; AFlow 62.50 / 53.33 / – / – / 65.43; MaAS 32.50 / 40.83 / – / – / 40.78; MAS-GPT 58.75 / 43.33 / – / – / 63.51; MAS-Orchestra 66.25 / 61.25 / 49.00 / 11.00 / 65.21. Claims more than 10x efficiency over strong baselines — [MAS-Orchestra](https://arxiv.org/html/2601.14652)
- Magentic-One: the ledger-based orchestrator versus a plain next-speaker selector is itself a "more model-directed control" comparison inside a fixed roster: minus 31% without the ledgers — [Magentic-One PDF](https://arxiv.org/pdf/2411.04468)

**Evidence against, or sharply qualifying, automatic structure.**
- "The Illusion of Multi-Agent Advantage" (Jwalapuram et al., Salesforce and collaborators; arXiv 11 Jun 2026, preprint): automatically generated systems "consistently underperform CoT-SC" on traditional reasoning datasets and on BrowseComp-Plus "despite being up to 10x more expensive"; on a synthetic diagnostic dataset with explicit decomposition, context separation and parallelisation potential, expert-architected systems consistently beat automatic ones on raw performance and cost-efficiency; the authors describe "architectural bloat" — [Jwalapuram et al. 2026](https://arxiv.org/abs/2606.13003) (abstract only; no numeric table read). A third-party blog lists the tested frameworks as DyLAN, MAS-Zero, ADAS, AFlow, MaAS and MAS-Orchestra — [Codex blog](https://codex.danielvaughan.com/2026/07/03/illusion-multi-agent-advantage-codex-cli-subagent-decision-framework-single-agent-cot-sc/) (unverified secondary source)
- This conflicts with MAS-Orchestra's own table from an overlapping author group, where MAS-Orchestra beats the SC agent on all five benchmarks (for example 66.25 versus 57.50 on AIME24) — [MAS-Orchestra](https://arxiv.org/html/2601.14652); contradicted in direction by [Jwalapuram et al. 2026](https://arxiv.org/abs/2606.13003). I could not reconcile these without the full text of the latter.
- MASS (Google): on Gemini 1.5 Pro, average across tasks: CoT 65.28; Self-Refine 66.90; Self-Consistency@9 68.18; ADAS 69.72; Multi-Agent Debate 70.26; MASS 78.79. Staged ablation: block-level prompt optimisation adds about 6%, topology optimisation about 3%, workflow-level prompt optimisation about 2%. Beneficial topologies are a small fraction of the space; on HotpotQA only debate helped (about 3%) and other building blocks failed to improve or degraded. ADAS "yields only subtle gains" because it does not optimise prompts. Recommendation: "optimize agents locally before scaling their topology" — [MASS](https://arxiv.org/html/2502.02533)
- OneFlow / "Rethinking the Value of Multi-Agent Workflow" (Xu et al.; arXiv 18 Jan 2026, preprint), GPT-4o-mini, HumanEval / MBPP / GSM8K / MATH / HotpotQA / DROP: AFlow multi-agent 90.1 / 78.8 / 93.6 / 55.6 / 72.1 / 83.1; AFlow run by a single agent 91.1 / 78.8 / 92.9 / 53.8 / 68.4 / 81.1; OneFlow single-agent 92.1 / 81.4 / 93.3 / 54.1 / 73.5 / 81.7. Cost in USD: AFlow multi-agent 0.198 / 0.393 / 1.134 / 2.343 / 1.438 / 0.771 versus OneFlow single-agent 0.020 / 0.063 / 0.387 / 0.677 / 0.278 / 0.284. Caveats: single-agent AFlow is 3.7 points lower on HotpotQA; costs are simulated for KV-cache reuse; equivalence assumes homogeneous models — [Xu et al. 2026](https://arxiv.org/html/2601.12307)
- Single agent with skills (Li; arXiv Jan 2026, preprint, described by its author as preliminary): compiling a multi-agent system into one agent with a skill library, GPT-4o-mini: GSM8K 94.0% to 92.0%, HumanEval 100.0% to 100.0%, HotpotQA 84.0% to 88.0%; average +0.7 points with 53.7% fewer tokens and 49.5% lower latency. Skill-selection accuracy stays above 90% up to about 20 skills, declines beyond 30, and is about 20% at 200 skills; hierarchical routing lifts 45–63% to 72–85% at 60 or more skills — [Li 2026](https://arxiv.org/html/2601.04748v2)
- AFlow's reported ADAS average (67.2) is below plain IO (72.8) and CoT (74.7) on GPT-4o-mini, i.e. an automatically discovered design underperforming the trivial baseline when re-run by another group — [AFlow PDF](https://arxiv.org/pdf/2410.10762)
- MAS-Orchestra's re-run of MaAS gives 32.50 on AIME24 versus 50.00 for a plain CoT agent, another automatic design below the trivial baseline when re-evaluated elsewhere — [MAS-Orchestra](https://arxiv.org/html/2601.14652)

**Direct self-organised versus assigned-structure experiments.**
- Dochkina, "Drop the Hierarchy and Roles" (arXiv 30 Mar 2026; single-author preprint; all quality scores from an LLM judge on synthetic tasks). Four main protocols: Coordinator (centralised), Sequential (fixed order, self-chosen roles), Broadcast, Shared (fully autonomous). Pilot (N=8, GPT-4.1-mini, L3+L4 average): Sequential 0.724, Coordinator 0.640, Broadcast 0.510, Shared 0.503; Sequential versus Shared +44%, Cohen's d = 1.86, p < 0.0001. Sequential versus Coordinator at N=16: Claude Sonnet 4.6 0.875 versus 0.767 (+14.1%), DeepSeek v3.2 0.829 versus 0.738 (+12.4%), GLM-5 0.800 versus 0.713 (+12.2%), all p < 0.001 — [Dochkina 2026](https://arxiv.org/html/2603.28990v1)
- Same paper, capability threshold: free-form versus fixed roles at N=8: Claude Sonnet 4.6 0.594 versus 0.574 (+3.5%); GLM-5 0.519 versus 0.574 (−9.6%). The author states the abstract's "25,000-task" figure while the series table totals about 20,810; the judge model changed between series; no multiple-comparison correction — [Dochkina 2026](https://arxiv.org/html/2603.28990v1)
- "Multi-Agent Teams Hold Experts Back" (Pappu et al., ICML 2026): self-organising LLM teams fail to match their best member even when told who the expert is, with "performance losses of up to 41.1% on ML benchmarks"; teams average expert and non-expert views, the tendency grows with team size, and the same consensus-seeking improves robustness to adversarial agents — [Pappu et al. 2026](https://arxiv.org/abs/2602.01011) (abstract only)
- Cursor (vendor blog, Jan 2026, anecdotal, no controlled metric): flat self-coordination with a shared file and locks made "Twenty agents ... slow down to the effective throughput of two or three"; with optimistic concurrency and no hierarchy "No agent took responsibility for hard problems or end-to-end implementation"; a prescribed planner/worker/judge hierarchy fixed most problems; an added integrator role "created more bottlenecks than it solved". Summary: "Too little structure and agents conflict, duplicate work, and drift" — [Cursor blog](https://cursor.com/blog/scaling-agents)
- Anthropic (vendor blog, Feb 2026): the opposite anecdote. Sixteen agents with no orchestrator and lock-file task claiming produced a working compiler, though merge conflicts were frequent and all agents converged on the same bug until the human restructured the task so that work could be partitioned — [Anthropic engineering blog](https://www.anthropic.com/engineering/building-c-compiler)

**Cost.**
- Anthropic: agents use about 4x the tokens of chat, multi-agent systems about 15x; token usage alone explained 80% of BrowseComp performance variance, and tokens, tool calls and model choice together 95%. A lead Opus 4 with Sonnet 4 subagents "outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval" (internal eval, LLM-judged rubric, about 20 starting queries) — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)
- Position paper "Towards a Science of Collective AI" (Fan et al.; arXiv 5 Feb 2026, preprint): proposes a "collaboration gain" metric Γ that compares a multi-agent system with a single agent given the same total resource budget, to separate "genuine collaboration gain from mere resource accumulation", and splits the design space into control-level static presets and information-level dynamics — [Fan et al. 2026](https://arxiv.org/abs/2602.05289)

### Inferences
- Pattern across sources: an automatic method wins in its own paper, then appears as a weak baseline in the next paper (ADAS in AFlow; AFlow and MaAS in MAS-GPT and MAS-Orchestra; all of them in the Illusion paper). Baseline strength, budget matching and re-implementation fidelity explain much of the reported gain; the effect of "automatic structure" as such is not cleanly isolated in any study I read.
- Where the comparison is cleanest (MASS ablation; OneFlow single-agent execution; skills compilation), structure contributes a few points at most, less than prompt quality, and can be reproduced by one agent on homogeneous models.
- Adaptive structure seems to help most where the task changes shape during execution (Captain Agent's data analysis; Anthropic's breadth-first research) and to matter least for short single-answer reasoning. This is my reading across papers, not a tested result.
- The Dochkina result is often summarised as "self-organisation wins", but its best protocol fixes the turn order and frees only role choice, the fully autonomous protocol was the worst, and weaker models did better with assigned roles. It supports "partial prescription plus model-chosen roles for strong models", not unconstrained self-organisation.

### Gaps
- No controlled study found that compares prescribed and model-chosen team structure on repository-scale software engineering with matched token budgets. The Cursor and Anthropic accounts are uncontrolled vendor anecdotes pointing in different directions.
- Full numeric tables of the Illusion paper, MaAS and G-Designer were not read; MaAS and G-Designer comparisons against fixed chain, star, tree and complete-graph topologies are therefore not recorded.
- Most head-to-head numbers use GPT-3.5, GPT-4o-mini or Gemini 1.5; whether they hold for 2026 frontier models is untested in the sources read, apart from Dochkina (LLM-judged) and SwarmBench.

## 4. Scaling the number of agents, and whether models choose a sensible number

### Takeaway
More identical agents help by sampling-and-voting with clear saturation, and gains depend on task difficulty and on how weak the base model is; structured teams show logistic growth and several "more agents hurt" cases. On whether models pick a sensible team size, the direct evidence is thin: one vendor report of early over-spawning ("50 subagents for simple queries") fixed by prompt rules, benchmark and practitioner reports of under-delegation, and a few 2026 benchmarks that measure delegation rate or parallelism without reporting chosen agent counts.

### Cited Findings

**Scaling.**
- "More Agents Is All You Need" / Agent Forest (Li et al., TMLR Oct 2024): sampling-and-voting. Accuracy gains from increasing ensemble size: 12% to 24% on GSM8K, 6% to 10% on MATH, 1% to 4% on Chess, 5% to 11% on MMLU, 4% to 9% on HumanEval. Llama2-13B with ensembling reaches 59% on GSM8K versus 54% for single Llama2-70B. Relative gains: GSM8K 69 / 37 / 16 and MATH 200 / 120 / 34 (%) for Llama2-13B / Llama2-70B / GPT-3.5-Turbo. "Gains increase then decrease by rising the inherent difficulty" — [Li et al. PDF](https://arxiv.org/pdf/2402.05120)
- MacNet, "Scaling Large Language Model-based Multi-Agent Collaboration" (Qian et al., ICLR 2025): agents in directed acyclic graphs; irregular topologies outperform regular ones; supports over a thousand agents; performance follows a "logistic growth pattern" as agents are added — [Qian et al. abstract](https://arxiv.org/abs/2406.07155) (abstract only)
- Dochkina 2026 (LLM-judged, synthetic tasks): quality flat from 64 to 256 self-organised agents (0.964, 0.962, 0.958, 0.967; Kruskal-Wallis p = 0.61); with fixed roles 0.954 (N=8) to 0.949 (N=64) while tokens rose 11.8%; about 45% of agents were idle at N=256 through self-abstention — [Dochkina 2026](https://arxiv.org/html/2603.28990v1)
- MASS: scaling agents with default prompts (self-consistency, self-refine, debate) saturates early; prompt-optimised agents are more token-efficient — [MASS](https://arxiv.org/html/2502.02533)
- DyLAN: a selected team of 3 beats the unselected team and a 4-agent debate — [DyLAN PDF](https://arxiv.org/pdf/2310.02170). AgentVerse: more maths reviewers produce more erroneous critiques — [AgentVerse PDF](https://arxiv.org/pdf/2308.10848). ChatEval: accuracy peaks at 3–4 roles and drops at 5 — [ChatEval, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.07201)
- "Should we be going MAD?" (Smit et al., ICML 2024 per search listing; arXiv v3 Jul 2024), MedQA with GPT-3.5: Society of Mind with 4 agents and 2 rounds scores 0.73 at cost about 3.46 per question versus 0.70 at about 1.73 with 2 agents — [Smit et al.](https://arxiv.org/html/2311.17371v3)
- Pappu et al. (ICML 2026): the expertise-averaging failure "grows with team size" — [Pappu et al. 2026](https://arxiv.org/abs/2602.01011) (abstract only)
- Claude Code documentation (vendor): "Start with 3-5 teammates for most workflows"; "Three focused teammates often outperform five scattered ones"; token costs scale linearly with teammates; returns diminish — [Claude Code docs](https://code.claude.com/docs/en/agent-teams)

**Does the model choose a sensible number? Over-spawning.**
- Anthropic (vendor): early versions made errors such as "spawning 50 subagents for simple queries", searching endlessly for nonexistent sources and sending each other excessive updates; the fix was explicit effort-scaling rules in the lead agent's prompt — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)
- SwarmBench (Gao et al., EMNLP 2026 Findings per arXiv listing; arXiv 31 Aug 2026): orchestrators create subagents at run time. "a higher parallelism rate does not necessarily lead to higher parallelism gain" (Kimi-k2.5 has the highest parallelism rate but not the highest gain); "weaker orchestrators often require more interactions and redundant execution without necessarily obtaining better results". The paper does not report numbers of subagents chosen — [SwarmBench](https://arxiv.org/html/2608.30661v1)
- "Model or Harness?" (Raj et al.; arXiv 30 Jul 2026, preprint): a 41-mode failure taxonomy for agents including multi-agent systems; a search digest says it includes an orchestrator launching five subagents in parallel despite dependencies between the pieces — [Raj et al. abstract](https://arxiv.org/abs/2607.28802) (the five-subagent example is via search summary, not confirmed in the abstract)

**Under-delegation.**
- MAS-Orchestra: reasoning-model orchestrators "often solve the task first and then delegate to only one simple sub-agent, even when that sub-agent is stronger"; instruction-tuned models made better orchestrator initialisations; under the one-sub-agent setting the trained orchestrator delegated the whole task 100% of the time after 20 steps — [MAS-Orchestra](https://arxiv.org/html/2601.14652)
- DecisionBench (Gao et al.; arXiv 18 May 2026, preprint): delegation rates range from 7.5% to 29.5% across awareness conditions at near-equal mean quality; a counterfactual ceiling with perfect single-step delegation is 15–31 percentage points above measured performance on every suite; cross-vendor self-preference in delegation is 1.5–3.7x chance — [DecisionBench](https://arxiv.org/abs/2605.19099) (via search summary of the arXiv page)
- Claude Code documentation (vendor) lists as known behaviours: "Sometimes the lead starts implementing tasks itself instead of waiting for teammates"; the lead "can stop early too, deciding the team is finished before all tasks are actually complete"; "Claude may sometimes use subagents instead of creating a team" — [Claude Code docs](https://code.claude.com/docs/en/agent-teams)
- Practitioner benchmark (blog, April 2026): all primary models did the whole job alone and ignored a registered, visible sub-agent — [akitaonrails blog](https://akitaonrails.com/en/2026/04/18/llm-benchmarks-part-2-multi-model/) (via search summary; anecdotal)
- Cursor (vendor): without hierarchy, agents "became risk-averse", avoided hard tasks and made small safe changes — [Cursor blog](https://cursor.com/blog/scaling-agents)

### Inferences
- Both failure directions are documented: unprompted over-spawning on easy tasks (Anthropic, early 2025 models) and under-delegation or do-it-myself behaviour (MAS-Orchestra, DecisionBench, Claude Code documentation). Which one dominates appears to depend on the model generation and on how the prompt frames delegation; in every vendor system examined the remedy was an explicit prompt heuristic for team size, i.e. a partial return to prescription.
- The "more agents" result for voting ensembles should not be read as support for larger collaborating teams: the cases where agents interact (reviewers, debaters, self-organising teams) are where negative returns appear.

### Gaps
- I found no paper that reports the distribution of team sizes chosen by frontier models when left free and compares it with an oracle or best fixed size per task. SwarmBench and ClawArena-Team come closest but do not report it in the material read.
- The over-spawning evidence is a single vendor sentence about pre-release behaviour; no quantified rate.

## 5. Do role descriptions or personas matter?

### Takeaway
For single models, expert personas do not reliably improve accuracy and can lower it. Inside multi-agent systems the picture is mixed: functional role prompts tied to a workflow step clearly matter in the authors' own ablations (ChatDev, ChatEval), while generic persona or "expert" labels show null or negative effects in several studies, and hand-written role-assignment baselines are routinely among the weakest in comparison tables.

### Cited Findings

**Null or negative.**
- Zheng et al. (Findings of EMNLP 2024): 162 personas, 2,410 factual questions, four model families; "adding personas in system prompts does not improve model performance across a range of questions" versus no persona; choosing the best persona per question would help but predicting it is often no better than random — [Zheng et al.](https://arxiv.org/abs/2311.10054)
- Wharton "Prompting Science Report 4: Playing Pretend" (arXiv Dec 2025, technical report): across six models on graduate-level benchmarks, expert personas generally did not beat a no-persona baseline; domain-mismatched experts sometimes lowered accuracy — [arXiv 2512.05858](https://arxiv.org/abs/2512.05858) (via search summary). A critique disputes the blanket conclusion — [arXiv 2603.20225](https://arxiv.org/abs/2603.20225) (via search summary)
- Ferreira et al. (arXiv 26 Sep 2026, preprint, small language models): "Persona prompting reduces accuracy"; a dose-response experiment suggests a "persona tax, not a diversity tax", with redundant personas hurting most and maximally diverse teams recovering part of the loss. Debate gains 3 to 7 points over single-agent inference on tasks with headroom but ties or loses to self-consistency at matched budget, at 1.6x wall-clock time and 3.4x token cost — [Ferreira et al. 2026](https://arxiv.org/abs/2609.35875) (abstract only)
- Hand-designed role baselines are weak in comparison tables: ADAS's "Role Assignment" baseline scores 65.8 / 30.1 / 64.5 / 31.1 versus CoT 64.2 / 28.0 / 65.4 / 29.2 (within noise on three of four) — [ADAS PDF](https://arxiv.org/pdf/2408.08435). AFlow's MultiPersona averages 75.1 versus CoT 74.7 and CoT-SC 76.0 — [AFlow PDF](https://arxiv.org/pdf/2410.10762). In Smit et al., Multi-Persona scored 0.58 on MedQA versus 0.60 for a single agent, and debate lowered its accuracy relative to the first agent's answer because of its "devil" agent — [Smit et al.](https://arxiv.org/html/2311.17371v3)
- Smit et al. also show the effect is tuning-dependent: prompting an agreement intensity of 90% moved Multi-Persona from worst to best in their MedQA comparison (about +15% on a USMLE subset) — [Smit et al.](https://arxiv.org/html/2311.17371v3)

**Positive.**
- ChatDev: removing role assignments drops Executability 0.8800 to 0.5800 and Quality 0.3953 to 0.2212 — [ChatDev, ar5iv](https://ar5iv.labs.arxiv.org/html/2307.07924)
- ChatEval: identical role descriptions give 53.8% accuracy (kappa 0.25), the same accuracy as a single agent (kappa 0.27); diverse personas give 60% (kappa 0.33) — [ChatEval, ar5iv](https://ar5iv.labs.arxiv.org/html/2308.07201)
- DyLAN: which role set is selected matters by subject (up to 25.0% on specific MMLU subjects), implying roles are not interchangeable, though the benefit comes from selection, not from adding personas — [DyLAN PDF](https://arxiv.org/pdf/2310.02170)
- Dochkina 2026: 8 agents invented 5,006 unique role names when free to choose; strong models did slightly better with self-chosen roles (+3.5%), a weaker model did worse (−9.6%) — [Dochkina 2026](https://arxiv.org/html/2603.28990v1)
- Cursor (vendor): assigns different models to planner and worker roles because "GPT-5.2 was a better planner than GPT-5.1-Codex"; adds "the prompts matter more" than harness and models — [Cursor blog](https://cursor.com/blog/scaling-agents)

**Survey-level.**
- A 2026 survey of multi-agent debate notes that persona diversity is usually assigned manually and not tested as an independent variable, making its benefit hard to isolate — [arXiv 2607.26212](https://arxiv.org/abs/2607.26212) (via search summary)

### Inferences
- A useful distinction for benchmark design: a "role" that changes what an agent is asked to do, what context it sees and what tools it has (ChatDev phases, Magentic-One's FileSurfer) is a structural variable; a "persona" that only labels the agent as an expert is a prompt-style variable with weak and unpredictable effect. The positive ablations are mostly of the first kind, the null results mostly of the second.
- Role diversity seems to matter more than role content (ChatEval; Ferreira et al.), consistent with roles acting as a decorrelation device.

### Gaps
- No study found that ablates role descriptions inside an orchestrator-worker coding system with a frontier 2026 model.
- The Wharton report and its critique were not read in primary form.

## 6. What do critical and sceptical papers conclude?

### Takeaway
The sceptical literature converges on three claims: multi-agent gains are often compute gains in disguise and vanish against budget-matched single-agent baselines; a single agent can reproduce a homogeneous multi-agent workflow at lower cost; and context fragmentation between agents is the main practical failure source. Practitioners who argued against multi-agent designs in mid-2025 had partly reversed by 2026, but towards tightly prescribed hub-and-spoke structures, not free-form teams.

### Cited Findings
- Zhang et al., "If Multi-Agent Debate is the Answer, What is the Question?" (arXiv Feb 2025, later retitled "Stop Overvaluing Multi-Agent Debate"; preprint): five debate methods, nine benchmarks, four models; "MAD methods fail to reliably outperform simple single-agent baselines such as Chain-of-Thought and Self-Consistency"; criticises "limited dataset overlap and inconsistent baselines"; model heterogeneity helps — [Zhang et al.](https://arxiv.org/abs/2502.08788) (abstract only)
- Smit et al., "Should we be going MAD?" (ICML 2024 per listing): debate does not reliably beat self-consistency or ensembling; MedQA with GPT-3.5: Medprompt 0.65, Society of Mind 0.64, Ensemble Refinement 0.64, ChatEval / Self-Consistency / single agent 0.60, Multi-Persona 0.58; debate systems are more hyperparameter-sensitive — [Smit et al.](https://arxiv.org/html/2311.17371v3)
- Jwalapuram et al. 2026: automatic multi-agent systems underperform CoT-SC at up to 10x cost; "architectural bloat" — [Jwalapuram et al. 2026](https://arxiv.org/abs/2606.13003) (abstract only)
- Xu et al. 2026 (OneFlow): single-agent execution is "a strong, cost-efficient baseline" for homogeneous workflows and should be a standard baseline; does not cover heterogeneous-model workflows — [Xu et al. 2026](https://arxiv.org/html/2601.12307)
- Li 2026: single agent with skills matches multi-agent accuracy (+0.7 points average) with 53.7% fewer tokens, until the skill library passes roughly 50–100 skills — [Li 2026](https://arxiv.org/html/2601.04748v2)
- Pappu et al. (ICML 2026): self-organising teams lose up to 41.1% relative to their best expert — [Pappu et al. 2026](https://arxiv.org/abs/2602.01011) (abstract only)
- MASS: most topologies do not help; prompts matter more than topology — [MASS](https://arxiv.org/html/2502.02533)
- MAS-Orchestra's controlled benchmark: multi-agent gains shrink as the sub-agent gets stronger; multi-agent is consistently better only on the robustness (data-poisoning) axis, where single-agent accuracy fell to near zero; gains are largest at the "edge of competence" — [MAS-Orchestra](https://arxiv.org/html/2601.14652)
- Cognition, "Don't Build Multi-Agents" (Walden Yan, vendor blog, 12 Jun 2025): principles "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results"; notes Claude Code subagents are not run in parallel with the main agent and are usually "only tasked with answering a question, not writing any code" — [Cognition blog](https://cognition.com/blog/dont-build-multi-agents)
- Cognition later shipped coordinator-plus-children "managed Devins" (19 Mar 2026) — [Cognition blog](https://cognition.ai/blog/devin-can-now-manage-devins) (via search summary); a third-party summary of an April 2026 Cognition essay says the company revised its earlier stance while keeping writes single-threaded — [ZenML summary](https://www.zenml.io/llmops-database/multi-agent-systems-in-production-code-generation-and-review-at-scale) (secondary source, unverified)
- Anthropic (vendor, Jun 2025): multi-agent is a poor fit for domains "where all agents must share the same context" or with many inter-agent dependencies; "most coding tasks" have fewer parallelisable parts than research — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)
- Earlier-covered sceptical work, one line each: MAST catalogues multi-agent failure modes ([2503.13657](https://arxiv.org/abs/2503.13657)); Tran and Kiela compare at equal budget ([2604.02460](https://arxiv.org/abs/2604.02460)); Kim et al. on scaling agent systems ([2512.08296](https://arxiv.org/abs/2512.08296)); the iso-call study ([2609.04217](https://arxiv.org/abs/2609.04217)); "Collaboration Tax" ([2608.22152](https://arxiv.org/abs/2608.22152)).

### Inferences
- The sceptical papers mostly attack multi-agent versus single-agent, not prescribed versus self-organised. Their relevance to this axis is indirect: if structure adds only a few points over a budget-matched single agent, then differences between two ways of choosing the structure will be small and hard to measure without tight budget control.
- The one sceptical result that speaks directly to the axis (Jwalapuram et al.) favours expert-prescribed structure over automatically generated structure, on a synthetic dataset built to make structure matter.

### Gaps
- Sceptical results are concentrated on reasoning and QA benchmarks with one-shot answers. Whether they transfer to long-horizon tasks that exceed a single context window (the case vendors cite for multi-agent) is not established by these papers.

## 7. Evaluation: should a benchmark fix the team structure or leave it free?

### Takeaway
I found no paper that argues the question head-on as a benchmark-design choice. The nearest things are (a) 2026 benchmarks that deliberately leave orchestration to the model and score it, while fixing the sub-agent pool for comparability; (b) a survey that recommends reporting the realised structure and cost instead of forcing a canonical graph; and (c) proposals for budget-matched "collaboration gain" metrics. The common design is a hybrid: free structure, fixed resources.

### Cited Findings
- SwarmBench (EMNLP 2026 Findings per listing): explicitly frames the shift "from 'designing a fixed team' to 'allowing models to organize a team dynamically'". 8 tasks x 50 examples covering decomposition, delegation and aggregation; the main agent cannot call tools or answer by itself and part of the context is hidden from it, so it must delegate; the subagent set is "not fixed before execution" and the orchestrator picks roles and backbone models from a pool. Metrics: task accuracy; Parallelism Rate (duration-weighted concurrent subagents) and Parallelism Gain (model plus tool latency over wall-clock); cost in USD over all calls; LLM-judged process quality for decomposition, delegation and aggregation (human-agreement correlations 0.684 to 0.801). Average accuracy as orchestrator: GPT-5.4 50.49, Claude-Sonnet-4-6 43.51, Qwen3.5-397b 40.62, Deepseek-v3.2 40.38, GLM-5.1 40.30, Gemini-3-flash 38.63, Doubao-seed-1-8 35.29, Claude-Haiku-4-5 33.05, Kimi-k2.5 32.81, Qwen3-30b 25.15; best single model 24.41 (GPT-5-mini). Limitation stated by the authors: the evaluation uses "a fixed subagent model pool, which improves comparability but may limit the generality of the conclusions" — [SwarmBench](https://arxiv.org/html/2608.30661v1)
- ClawArena-Team (Xiong et al.; arXiv 30 Jun 2026, preprint): argues existing benchmarks do not isolate one model's management ability. 41 multi-turn multimodal scenarios, 258 evaluation rounds; a text-only main agent with partial workspace access commands a fixed, locally served subagent pool, held constant so that score differences reflect management skill. Execution-based scoring, no LLM judge. The Subagent-Management Score multiplies task correctness by a least-privilege and modality-routing factor. Findings: no model exceeds 50% workspace-permission precision; across twelve models API cost varies by more than 100x while overall score varies by less than 4x; most scores fall within a 9.9-point band while orchestration behaviours differ by more than an order of magnitude — [ClawArena-Team](https://arxiv.org/abs/2606.31174) (abstract-level summary)
- DecisionBench (preprint, May 2026): scores "emergent delegation" by giving the orchestrator `call_model` and `read_profile` tools over a pool of 11 peer models from 7 vendor families on GAIA, tau-bench and BFCL multi-turn; mean end-task quality barely changes across conditions while delegation rates move from 7.5% to 29.5%, so "quality-only evaluation would miss the orchestration signal"; reports a counterfactual perfect-routing ceiling 15–31 points above measured performance — [DecisionBench](https://arxiv.org/abs/2605.19099) (via search summary)
- MAS-Orchestra's MasBench (preprint): controls task structure along five axes (depth, horizon, breadth, parallel, robustness) and controls the allowed "degree of MAS" (at most one sub-agent versus unconstrained) as an experimental variable, so that the benefit of freedom to add agents can be measured per task type — [MAS-Orchestra](https://arxiv.org/html/2601.14652)
- Jwalapuram et al. 2026 build a synthetic diagnostic dataset with "explicit task decomposition, context separation and parallelization potential" specifically to compare expert-fixed and automatically generated architectures — [Jwalapuram et al. 2026](https://arxiv.org/abs/2606.13003) (abstract only)
- Yue et al. survey (Mar 2026): "The point is not to force a single canonical graph, but to make evaluation robust enough" for structural claims; "workflow papers should not report only" the answer but also the realised workflow, its variation across inputs and its cost; recommends graph-level metrics (depth, width, communication volume, edit count), tokens, calls, latency and dollars, with "Cost-per-success is often more informative than raw cost"; warns "Without those details, apparent gains are hard to attribute"; says "static optimization is often sufficient when three conditions hold at once" (constrained operator space, trustworthy evaluator, repetitive workload); recommends perturbation tests including strict budget caps — [Yue et al. 2026](https://arxiv.org/html/2603.22386v1)
- Fan et al. position paper (Feb 2026): calls for the collaboration gain metric Γ, measured against a single agent "allocated a total resource budget" equal to the team's, as the standard for attributing gains to structure instead of to resources — [Fan et al. 2026](https://arxiv.org/abs/2602.05289)
- Zhang et al. 2025 (debate critique) argue that inconsistent baselines and limited dataset overlap undermine multi-agent claims — [Zhang et al.](https://arxiv.org/abs/2502.08788) (abstract only)
- Anthropic's evaluation practice for a free-structure system (vendor): end-state and rubric-based LLM judging (factual accuracy, citation accuracy, completeness, source quality, tool efficiency) on about 20 initial queries plus human testing, because agents take different valid paths — [Anthropic engineering blog](https://www.anthropic.com/engineering/multi-agent-research-system)

### Inferences
- The emerging convention in 2026 orchestration benchmarks is: fix what makes scores comparable (sub-agent pool, tools, sometimes the constraint that the main agent cannot do the work itself), leave free what the benchmark wants to measure (how many agents, which roles, what is delegated, when to stop), and report process metrics alongside task accuracy. None of the benchmarks read fixes the number of agents.
- Two design devices recur for making free-structure runs interpretable: forcing delegation (SwarmBench's main agent cannot use tools; ClawArena-Team's leader has partial access) and treating the freedom itself as a controlled variable (MAS-Orchestra's degree-of-MAS; DecisionBench's awareness conditions). A benchmark that wants both comparability and a measure of organisational ability could run a prescribed-structure arm and a free-structure arm under the same budget; I did not find a published benchmark that does exactly this, though MAS-Orchestra and Jwalapuram et al. come close.
- ClawArena-Team's and DecisionBench's shared observation, that end-task scores compress while orchestration behaviour varies widely, is an argument that a benchmark fixing structure, or scoring only the final output, would hide most of the between-model variation in organisational skill. This is my synthesis; neither paper states it as a prescription about fixing structure.

### Gaps
- No paper found that explicitly argues "benchmarks should fix team structure for comparability" as a position; the comparability argument appears only in limited form (fixed sub-agent pool in SwarmBench and ClawArena-Team, fixed budget in Fan et al. and the earlier-covered equal-budget studies).
- SwarmBench's process-quality scores depend on an LLM judge; ClawArena-Team and DecisionBench details beyond the abstract level were not read, so their exact scoring formulas and per-model results are not recorded here.
- No orchestration benchmark found that targets multi-service software engineering with a free team structure and execution-based scoring of both outcome and delegation decisions.
