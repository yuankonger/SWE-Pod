# Multi-agent LLM benchmarks and datasets for software engineering (state of the field to November 2026)

Research date: 2026-11-12. Already covered elsewhere and mentioned here only for context: CooperBench (arXiv 2601.13295), AsynCodeBench (arXiv 2609.32662), MAST (arXiv 2503.13657).

How to read these notes
- Each key question is a section; inside it, bullets are tagged with the benchmark name so a row can be assembled per benchmark.
- "Opened" means I read the paper's HTML or abstract page in this session. "Snippet only" means the number came from a search-result summary of the linked page and was not checked against the full text.
- Three groups are used throughout:
  - Group A, built to test several agents on code: ParallACT, NP-Bench, SyncBench, MultiAgentBench (coding scenario), the sub-agent concurrency study (arXiv 2610.10263), TheAgentCompany, EntCollabBench, ClawArena-Team, SwarmBench, plus the datasets AgenticFlict and BulkPR-Bench.
  - Group B, task sets on which multi-agent systems are evaluated but which do not themselves define a team: SRDD, SoftwareDev, ProjectDev, DevBench, E2EDevBench, ProjDevBench, Commit0, MLE-bench, SWE-bench (MAGIS, CodeR, Agyn, EvoMAS, DeLM).
  - Group C, checked and found not to be multi-agent or not about code: CodeArena, AgentBoard, MASBench.

## 1. What are the tasks, how many, and where do they come from?

### Takeaway
Purpose-built multi-agent coding benchmarks are few and recent (2025–2026) and mostly derive tasks from existing single-agent sets (SWE-Bench Pro, SRDD, SWE-bench Verified) or hand-scripted scenarios. The older "multi-agent" evaluation sets (SRDD, SoftwareDev, ProjectDev) are short natural-language requirement prompts with no repository.

### Cited Findings
Group A
- ParallACT (preprint, submitted 30 Oct 2026; Mediratta, Xiao, Stone, Biswas, Stengel-Eskin): 155 instances (85 contradictory, 70 complementary) built on SWE-Bench Pro, 11 open-source repositories. Requirement A comes from SWE-Bench Pro; requirement B is hand-written (27 seed instances) or generated by "GPT 5.6 Sol" (128 instances). Complementary tasks are separately useful but must share an interface; contradictory tasks need incompatible edits to the same code. — [arXiv abs](https://arxiv.org/abs/2611.00314), [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench (preprint, 5 Oct 2026): Tier A is nine hand-constructed scripted scenarios (shared-file, contract, cross-repo fan-out, an independent control, concurrent/high-N variants) plus a sweep of N ∈ {2, 4, 8, 16, 32} agents on one hot file; Tier B is live agents on contract migration, fan-out with N ∈ {2, 4, 8}, a same-file assignment case, and a memory-continuity sandbox, with K=15 (Opus 4.8, contract cell) and K=3 to 5 elsewhere. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- SyncBench / SyncMind (ICML 2025, PMLR v267): 24,332 out-of-sync instances from 21 GitHub repositories with executable tests; the agent's view of a shared codebase has gone stale because collaborators changed it. Snippet only. — [arXiv 2502.06994](https://arxiv.org/abs/2502.06994), [PMLR](https://proceedings.mlr.press/v267/guo25l.html)
- MultiAgentBench / MARBLE, coding scenario (arXiv 3 Mar 2025; ACL 2025 per the ACL Anthology listing): six scenarios, "100 test cases per task"; coding tasks are "developed through an adaptation of the SRDD dataset", generated with LLaMA-3-70B-instruct. The coding task count is not stated separately in the appendix. — [arXiv HTML](https://arxiv.org/html/2503.01935v1), [ACL Anthology](https://preview.aclanthology.org/setup/2025.acl-long.421)
- "When Sub-Agents Work in Parallel" (preprint, 7 Oct 2026; an empirical study, not a new task set): 354 tasks sampled from SWE-bench Verified (100 of 500), RepoZero Py2JS (100 of 400), RepoZero C2Rust (50 of 200), NL2Repo (26 of 104), ProgramBench (50 of 200), LoopsBench (28 of 112); 2,124 executions. — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- TheAgentCompany (arXiv Dec 2024, v3 revised 10 Sep 2025; venue not shown on the page): 175 tasks in a simulated software company; Appendix B lists 69 SWE, 28 PM, 14 DS, 15 Admin, 29 HR, 12 Finance (these sum to 167, not 175). Manually curated by co-authors and industry experts, about 3,000 person-hours. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- EntCollabBench (preprint, 9 May 2026): 300 tasks (160 workflow, 40 workflow multi-task, 80 approval, 20 approval multi-task). Only partly software: the workflow subset includes IT incident handling and engineering tasks such as submitting pull requests and code review on Gitea. — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- ClawArena-Team (preprint, 30 Jun 2026): 41 multi-turn, multimodal, multi-directory scenarios, 258 evaluation rounds, 72 staged updates; domain is workspace management, and whether any are coding tasks is not stated on the abstract page. — [arXiv abs](https://arxiv.org/abs/2606.31174)
- SwarmBench (EMNLP 2026 Findings, arXiv 31 Aug 2026): tests whether an LLM can act as a swarm orchestrator. Task count and domain are not on the abstract page; a search summary gives "8 tasks and 400 samples" (snippet only). — [arXiv abs](https://arxiv.org/abs/2608.30661)
- AgenticFlict (dataset, preprint, 4 Apr 2026, v2 12 May 2026): 142K+ agentic pull requests from 59K+ GitHub repositories, 107K+ processed by merge simulation, 29K+ with merge conflicts, 336K+ conflict regions. — [arXiv abs](https://arxiv.org/abs/2604.03551)
- BulkPR-Bench (preprint, 3 Aug 2026): 581 newly authored candidate PRs on frozen snapshots of 18 real repositories; one agent must order and filter a queue of interacting PRs. — [arXiv abs](https://arxiv.org/abs/2608.02685)

Group B
- SRDD (ChatDev): 1,200 software requirement prompts, five categories and 40 subcategories, requirement text only. Snippet only. — [survey 2511.00872](https://arxiv.org/pdf/2511.00872), [ChatDev follow-up 2312.17025](https://arxiv.org/pdf/2312.17025)
- SoftwareDev (MetaGPT): 70 software development tasks, requirement-only input; the MetaGPT paper reports its detailed metrics on a subset. Snippet only. — [MetaGPT 2308.00352](https://arxiv.org/pdf/2308.00352), [E2EDevBench paper](https://arxiv.org/pdf/2511.04064)
- ProjectDev (AgileCoder): listed at 14 tasks with requirement-only inputs by a later benchmarking study; a search of the AgileCoder paper did not confirm the count. — [E2EDevBench paper](https://arxiv.org/pdf/2511.04064), [AgileCoder 2406.11912](https://arxiv.org/pdf/2406.11912)
- DevBench (arXiv Mar 2024): 22 repositories in Python, C/C++, Java and JavaScript, covering software design, environment setup, implementation, acceptance testing and unit testing. Snippet only. — [arXiv HTML](https://arxiv.org/html/2403.08604v2), [GitHub](https://www.github.com/open-compass/DevBench)
- E2EDevBench (preprint, 6 Nov 2025): 50 real PyPI projects, 10 per quarter from Q1 2024 to Q1 2025. — [arXiv HTML](https://arxiv.org/html/2511.04064)
- ProjDevBench (preprint, 2 Feb 2026): 20 programming problems across 8 categories. — [arXiv abs](https://arxiv.org/abs/2602.01655)
- Commit0 (preprint, 2 Dec 2024): 54 Python libraries (lite split: 16); the agent gets a specification PDF, a starter repository with stubbed functions, and unit tests. — [arXiv HTML](https://arxiv.org/html/2412.01769)
- SWE-bench as host for multi-agent systems: MAGIS (NeurIPS 2024) on SWE-bench; CodeR on SWE-bench Lite (300 issues); Agyn on "SWE-bench 500"; DeLM and EvoMAS on SWE-bench Verified. — [MAGIS](https://arxiv.org/abs/2403.17927v2), [CodeR](https://arxiv.org/html/2406.01304v3), [Agyn](https://arxiv.org/html/2602.01465v2), [DeLM](https://arxiv.org/html/2606.10662), [EvoMAS](https://arxiv.org/pdf/2602.06511)

Group C
- MASBench (preprint, v2 4 Nov 2026) partitions information between agents but has no software tasks: Reasoning (300), Scheduling (200), Game (100). — [arXiv HTML](https://arxiv.org/html/2610.04672)
- CodeArena (ACL 2025 demo): "collective" refers to score recalibration across models, not to agents working together. AgentBoard: single agent, 9 tasks in 4 categories, "multi-turn" means agent–environment rounds. — [CodeArena](https://preview.aclanthology.org/watermark/2025.acl-demo.48), [AgentBoard](https://arxiv.org/pdf/2401.13178)

### Inferences
- Only ParallACT, NP-Bench, CooperBench and AsynCodeBench define tasks whose structure requires more than one agent editing one codebase; everything in Group B is a single-agent-solvable task on which a team is optionally run.
- No benchmark found has agents own separate deployed services with contracts between them. NP-Bench's "contract" and "cross-repo fan-out" scenarios (producer changes a contract, N consumers adapt) are the nearest, and they are nine hand-built scenarios, not a task corpus.

### Gaps
- MLE-bench and MLAgentBench task counts and sources were not opened this session.
- SW-A²-Bench (arXiv 2604.04226; agents generated from repositories interoperating over A2A) surfaced only as a search snippet and was not opened. — [arXiv HTML](https://arxiv.org/html/2604.04226)
- SWE-EVO (arXiv 2512.18470) mentions "multi-agent orchestration" in a snippet; not opened, appears to be single-agent long-horizon.
- No benchmark named "SWE-bench Multi-agent", TeamBench, SWE-Team or similar was found by title search.

## 2. How many agents, and is the number fixed, varied, or left to the system?

### Takeaway
Three patterns exist: fixed at two (ParallACT), swept as an experimental variable (NP-Bench 2–32, DeLM 2 or 4), or chosen by the system under test (native sub-agent features, the Group B frameworks).

### Cited Findings
- ParallACT: two agents in all experiments, "the minimal unit"; scaling to n is future work. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: varied by the benchmark; 2 to 32 concurrent agents in deterministic runs, 2, 4 or 8 consumers in live fan-out. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- Sub-agent concurrency study: left to the system. The main agent decides whether and how many sub-agents to spawn; the only experimental switch is feature on or off. Mean sub-agents created: 6.69 (easy), 7.53 (medium), 15.84 (hard); on LoopsBench hard tasks Claude Code created 133.69 per task (peak 25.46 concurrent), Kimi Code 67.00 (peak 37.46), Codex peaks between 1.21 and 3.00. — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- MultiAgentBench: the agent-count ablation (1, 3, 5, 7 agents) was run only on the Research scenario; the coding scenario's agent count is not stated. — [arXiv HTML](https://arxiv.org/html/2503.01935v1)
- TheAgentCompany: one agent under test plus simulated colleagues; the roster lists 17 colleagues, and 41 tasks involve them. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- EntCollabBench: fixed at 11 agents (8 operational, 3 approval) across six departments. — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- ClawArena-Team: a fixed, locally served sub-agent pool commanded by the model under test; pool size not stated on the abstract page. — [arXiv abs](https://arxiv.org/abs/2606.31174)
- DeLM (system paper): n = 2 or n = 4 peer agents, varied. — [arXiv HTML](https://arxiv.org/html/2606.10662)
- E2EDevBench: three fixed architectures of 1, 2 and 3 agents. — [arXiv HTML](https://arxiv.org/html/2511.04064)
- Agyn on SWE-bench: four roles, fixed configuration across tasks. MAGIS: four agent types. — [Agyn](https://arxiv.org/html/2602.01465v2), [MAGIS](https://arxiv.org/abs/2403.17927v2)
- Commit0, ProjDevBench, DevBench, SRDD, SoftwareDev, ProjectDev: the benchmark does not fix an agent count; it is whatever the evaluated framework uses. Commit0's paper evaluates single-agent loops only (SDE-I, OpenHands). — [Commit0](https://arxiv.org/html/2412.01769), [ProjDevBench](https://arxiv.org/abs/2602.01655)

### Inferences
- No coding benchmark found sweeps team size as a controlled variable on real repository tasks with live LLM agents beyond N=8 (NP-Bench's 16 and 32 are scripted, deterministic runs).

### Gaps
- SwarmBench agent counts not stated on the abstract page.

## 3. Are roles prescribed by the benchmark or chosen by the system?

### Takeaway
Benchmarks built around parallel work prescribe ownership (a requirement, a scope, a producer or consumer side) rather than job titles; job-title roles (manager, coder, reviewer, tester) belong to the systems being evaluated, not to the benchmarks, with EntCollabBench and MultiAgentBench as exceptions.

### Cited Findings
- ParallACT: no orchestrator; each agent represents one principal with one requirement. An "Orchestrator" condition exists but is a single-agent baseline that delegates to sub-agents. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: producer and consumer roles in contract scenarios; under the planning arm each agent gets an allowed and forbidden file scope. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- MultiAgentBench coding: prescribed specialisms: "Each agent specializes in a specific domain, such as debugging, code execution, or writing test cases." — [arXiv HTML](https://arxiv.org/html/2503.01935v1)
- EntCollabBench: prescribed named roles with role-specific system prompts and service access (for example "it_service_desk_l1"). — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- TheAgentCompany: colleagues have prescribed profiles (name, role, responsibilities, project affiliations); the tested agent is one employee. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- Sub-agent concurrency study: system-chosen; the main agent plans, spawns, reconciles and verifies; sub-agents are created on demand. — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- E2EDevBench: prescribed by the study: Developer–Tester and Designer–Developer–Tester, run sequentially. — [arXiv HTML](https://arxiv.org/html/2511.04064)
- System-level roles on SWE-bench: MAGIS uses Manager, Repository Custodian, Developer, QA; CodeR uses reproducer, fault localizer, editor, verifier under pre-defined task graphs; Agyn uses manager, researcher, engineer, reviewer. MAGIS and CodeR role lists are snippet only. — [MAGIS](https://arxiv.org/abs/2403.17927v2), [CodeR](https://arxiv.org/html/2406.01304v3), [Agyn](https://arxiv.org/html/2602.01465v2)
- DeLM: no fixed roles; peers claim items from a shared queue. — [arXiv HTML](https://arxiv.org/html/2606.10662)

### Inferences
- "Per-module owner" as a benchmark-prescribed role appears only in NP-Bench (scope assignment) and, per earlier research, AsynCodeBench.

### Gaps
- ChatDev, MetaGPT and AgileCoder role lists were not re-verified from the primary papers this session.

## 4. What does each agent see? Is information or repository access partitioned?

### Takeaway
Real information partition is rare in coding benchmarks: ParallACT withholds the partner's requirement, NP-Bench assigns file scopes, EntCollabBench isolates tools by department, and TheAgentCompany hides facts with simulated colleagues. Most others give every agent the full task and a shared workspace.

### Cited Findings
- ParallACT: each agent sees only its own requirement and the initial repository; reference solutions and tests are withheld unless a gold-test condition is used; a "communication oracle" condition gives each agent the partner's requirement. Parallel agents start from the same base and keep edits separate until merge; sequential and reentrant conditions share one workspace across turns. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: an agent's declared scope is the files it may write and the contracts it consumes; coordination information differs by arm (none, a deliberately vague warning, or an explicit allowed/forbidden scope plus the exact contract migration). Each agent works in its own git worktree, which the daemon polls. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- SyncBench: the agent's belief about the repository is stale relative to collaborators' changes; that staleness is the partition. Snippet only. — [arXiv 2502.06994](https://arxiv.org/abs/2502.06994)
- Sub-agent concurrency study: sub-agents write to a shared workspace, which produces write conflicts and environment contamination; sub-agents receive whatever the main agent passes them (in one example, specific source files and the shared interface). — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- EntCollabBench: "Role isolation is strictly enforced"; agents use only their department's tools with their own service identity token and keep isolated memory. — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- ClawArena-Team: the main agent perceives only text and directly accesses only part of the workspace, so it must route work to sub-agents; scoring penalises over-granting permissions. — [arXiv abs](https://arxiv.org/abs/2606.31174)
- TheAgentCompany: some task information is held only by simulated colleagues and must be requested via chat. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- Agyn: "Each agent operates within its own isolated execution environment" and agents "do not share a single global context or prompt". — [arXiv HTML](https://arxiv.org/html/2602.01465v2)
- DeLM: each peer has its own session and workspace and produces its own complete solution; sharing happens through an append-only log with file snapshots. — [arXiv HTML](https://arxiv.org/html/2606.10662)
- MultiAgentBench coding: what agents see is not stated. — [arXiv HTML](https://arxiv.org/html/2503.01935v1)

### Inferences
- Worktree-per-agent with a real merge at the end is used by ParallACT and NP-Bench; the vendor sub-agent features studied in 2610.10263 instead share one workspace, and 26.5% of that study's failure-pattern instances are concurrent writes (see section 9).

### Gaps
- No benchmark found partitions repository read access so that an agent cannot read another owner's source.

## 5. How do agents communicate, and is communication measured?

### Takeaway
Channels range from none, through shared files or inboxes, to pull-request review; only ParallACT, MultiAgentBench, TheAgentCompany and SyncBench score or analyse communication itself, and two of those rely on an LLM judge.

### Cited Findings
- ParallACT: a shared append-only file or per-agent Redis inboxes, framed as free-form "messaging" or explicit "synchronization"; message timing and content are analysed with an LLM judge validated against human labels. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: no agent-to-agent chat; a local daemon (SQLite store, MCP tools) polls worktrees, routes events and delivers assignments at register or sync time. Outcomes are measured from the merge, "rather than agent self-reports". — [arXiv HTML](https://arxiv.org/html/2610.07261)
- MultiAgentBench: Communication Score and Planning Score, each a five-point LLM rating; Coordination Score is their average; communication score is 0 if no communication occurs. — [arXiv HTML](https://arxiv.org/html/2503.01935v1)
- SyncBench: measures assistance-seeking rate; agents' willingness to ask collaborators was at or below 4.86%. Snippet only. — [arXiv 2502.06994](https://arxiv.org/abs/2502.06994)
- TheAgentCompany: Rocket.Chat direct messages and channels; a "Collaboration" checkpoint type scores interactions with colleagues. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- EntCollabBench: explicit delegation tools (for example "ask_<peer>_by_http"), peer-to-peer, with a delegation-depth cap. — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- Agyn: "Agents in our system do not communicate directly with each other"; coordination goes through the manager and through GitHub pull-request reviews with inline comments. — [arXiv HTML](https://arxiv.org/html/2602.01465v2)
- DeLM: append-only shared log of fact, fail and completion-summary entries, plus a task queue with exclusive claims; shared-context reads cost 1.7–3.7% of task cost with Opus 5.5 and 7.7–17.7% with GPT-6-Astra. — [arXiv HTML](https://arxiv.org/html/2606.10662)
- E2EDevBench: "simplified inter-agent collaboration, modeling it as a sequential handoff of tasks". — [arXiv HTML](https://arxiv.org/html/2511.04064)
- MASBench (not coding) counts inter-agent message tokens and reports score per 1,000 communication tokens, without an LLM judge. — [arXiv HTML](https://arxiv.org/html/2610.04672)

### Inferences
- A deterministic communication-cost metric (tokens exchanged between agents) exists in MASBench but was not found in any coding benchmark; ParallACT reports total effective tokens per condition, which captures the cost of communication only indirectly.

### Gaps
- ParallACT's message counts and timing statistics were in a part of the page that could not be extracted.

## 6. What baselines are included?

### Takeaway
ParallACT has the fullest baseline ladder (single-agent oracle, orchestrator, sequential, reentrant, unaware, aware, messaging, communication oracle). Equal-token-budget single-agent baselines are almost absent from benchmarks and appear only in system papers (EvoMAS). No human-team baseline was found.

### Cited Findings
- ParallACT: single-agent oracle given both requirements, orchestrator, sequential A→B, reentrant ABAB, parallel unaware, parallel aware, parallel message, parallel sync, communication oracle, and oracle or parallel with gold tests. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: three arms: C0 no coordination, C1-detect reactive detection with a vague warning, C1-plan proactive scope assignment and merge ordering. No single-agent baseline is described. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- Sub-agent concurrency study: same harness, model, prompt, environment and time budget with the sub-agent feature disabled; tokens are not equalised. — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- E2EDevBench: SDAgent-Single against two multi-agent variants on one code base (SWE-Agent), maximum 200 agent steps per task. — [arXiv HTML](https://arxiv.org/html/2511.04064)
- DeLM: single harness run, the same harness with native sub-agents, AOrchestra (centralised), mini-SWE-agent; cost per task and per submission reported for each. — [arXiv HTML](https://arxiv.org/html/2606.10662)
- EvoMAS (preprint, Feb 2026): a budget-matched SWE-bench Verified comparison in which a single agent is looped to the multi-agent system's token budget. Snippet only. — [arXiv 2602.06511](https://arxiv.org/pdf/2602.06511)
- Agyn: single-agent baselines are other teams' published scores with different models and reasoning settings, not a matched run. — [arXiv HTML](https://arxiv.org/html/2602.01465v2)
- TheAgentCompany: compares a single-agent framework (OpenHands CodeAct) with one multi-agent framework (OWL-RolePlay) on different models. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- EntCollabBench: no all-in-one single-agent baseline in the part of the paper read, despite the title. MultiAgentBench: no single-agent baseline for coding. — [EntCollabBench](https://arxiv.org/html/2605.08761v1), [MultiAgentBench](https://arxiv.org/html/2503.01935v1)
- ProgramBench's authors state that on SWE-bench "multi-agent variants there haven't shown consistent gains" and that they plan to use ProgramBench to measure where multi-agent approaches help. Snippet only. — [arXiv HTML](https://arxiv.org/html/2605.03546v1)

### Inferences
- A no-communication team baseline exists in ParallACT (parallel unaware) and NP-Bench (C0); a human-team baseline exists nowhere in the material found.

### Gaps
- Whether EntCollabBench's appendix has a single-agent baseline (last ~90K characters unread).

## 7. How is it scored, and is cost reported or bounded?

### Takeaway
The strongest designs score the merged result with hidden acceptance tests after a real git merge (ParallACT, NP-Bench). Cost is reported in most 2026 work but bounded in almost none; the older requirement-prompt sets use human or heuristic ratings.

### Cited Findings
- ParallACT: joint success requires both requirements' acceptance tests to pass after merging; per-side partial completion also reported. Merge policies are concatenation, Git merge and model-based reconciliation, with the best counted. Cost is "effective tokens" = input + cache-write + 0.1·cache-read + 5·output, relative to the oracle; wall-clock time not stated. — [arXiv HTML](https://arxiv.org/html/2611.00314)
- NP-Bench: real git merges of agent branches; clean-tree success rate (clean merge and a passing post-integration acceptance check), merge conflicts, wasted LOC, scope leakage, consumer-adaptation rate, repeated-mistake rate, merge-order correctness. Per-run monetary cost not stated. — [arXiv HTML](https://arxiv.org/html/2610.07261)
- Sub-agent concurrency study: official tests of each benchmark (task pass and mean test pass); reports shell calls, execution minutes and tokens; total 11.2 billion tokens, $20,780.02 at standard API rates; time budget held equal between modes. — [arXiv HTML](https://arxiv.org/html/2610.10263v1)
- MultiAgentBench coding: five-point ratings on Instruction-Following, Executability, Consistency and Quality in a two-stage process; the main text calls coding "rule-based" while the appendix describes ratings, so the judge type is unclear. Token usage is reported only for the Research protocol comparison. — [arXiv HTML](https://arxiv.org/html/2503.01935v1)
- TheAgentCompany: checkpoints with point values; S_partial = 0.5 · (Result/Total) + 0.5 · S_full; an LLM judge (Claude-3-5-Sonnet-20241022) is used in 51 tasks (29%) as a fallback; steps (LLM calls) and dollar cost per task are reported. — [arXiv HTML v3](https://arxiv.org/html/2412.14161v3)
- EntCollabBench: execution traces and database state diffs for workflows, deterministic policy adjudication for approvals, each step judged by a three-model majority vote; agent-, subtask- and task-level pass rates; token cost per task in appendix. — [arXiv HTML](https://arxiv.org/html/2605.08761v1)
- ClawArena-Team: Subagent-Management Score multiplies task correctness by a least-privilege and modality-routing factor; execution-based, no LLM judge; API cost varies by over 100x across models. — [arXiv abs](https://arxiv.org/abs/2606.31174)
- E2EDevBench: Implementation Rate (requirements unanimously judged implemented across three LLM-judge runs) plus test pass rate; tokens and dollars per project reported. — [arXiv HTML](https://arxiv.org/html/2511.04064)
- Commit0: unit test pass rate; dollar cost reported for many configurations. — [arXiv HTML](https://arxiv.org/html/2412.01769)
- ProjDevBench: online-judge testing plus LLM-assisted code review. — [arXiv abs](https://arxiv.org/abs/2602.01655)
- SRDD uses heuristic metrics (completeness, executability, consistency, quality); SoftwareDev relies on human ratings; ProjectDev executability is a human-assessed percentage of requirements met. Snippet only. — [arXiv 2510.14509](https://arxiv.org/html/2510.14509v1), [AgileCoder](https://arxiv.org/html/2406.11912v2)
- BulkPR-Bench: Relational Delivery Score and Global Safety-Gated Yield over the realised merge trace, with hidden safety checks and an exact oracle for the largest safe subset. — [arXiv abs](https://arxiv.org/abs/2608.02685)
- AgenticFlict: deterministic merge simulation; no agent is scored. — [arXiv abs](https://arxiv.org/abs/2604.03551)

### Inferences
- Per-dependency or per-contract checks appear in NP-Bench (consumer-adaptation rate) and, per earlier research, AsynCodeBench; elsewhere scoring is whole-task.
- Only step caps (E2EDevBench 200 steps) and equal time budgets (2610.10263) bound cost; no benchmark found fixes a token budget across single- and multi-agent conditions.

### Gaps
- DevBench's exact metrics per stage were not opened.

## 8. What does each benchmark say it is evaluating?

### Takeaway
Stated constructs split into coordination under conflicting or interlocking edits (ParallACT, NP-Bench), recovery from stale state (SyncBench), delegation and orchestration skill of a lead model (ClawArena-Team, SwarmBench, the concurrency study), and end-to-end task success with collaboration as a side condition (the rest).

### Cited Findings
- ParallACT: coordination and communication strategies for multiple coding agents in a shared codebase when "multiple agents are needed by necessity" because separate developers issue independent requests; claims coordination failures that a single agent with full information avoids. — [arXiv abs](https://arxiv.org/abs/2611.00314), [arXiv HTML](https://arxiv.org/html/2611.00314)

### Inferences
- "Collaboration gain over a single agent" is rarely the stated construct. ParallACT frames the single agent as an upper bound, not a competitor, on the grounds that multiple principals make multiple agents unavoidable.
- Review quality and conflict resolution as explicit constructs were found only outside team benchmarks (c-CRAB for code review agents, arXiv 2603.23448, snippet only; AgenticFlict for conflicts as a dataset).

### Gaps
- No benchmark found states "delegation quality" as a scored construct on repository tasks with hidden tests; ClawArena-Team scores it on workspace-management tasks.

## 9. Headline results, especially multi-agent against single-agent

### Takeaway
Across 2025–2026 sources, parallel agents without strong coordination do far worse than one agent given everything, and vendor sub-agent features raise token use by 1.41–3.31x with mixed accuracy effects. Reported multi-agent gains come from system papers evaluating their own designs.

### Inferences
- Results where a team beats one agent (DeLM, NP-Bench's planner, Agyn, EvoMAS) are all reported by the authors of the winning system; the two independent-style studies (ParallACT, 2610.10263) both find parallel agents costlier and often less accurate.
- The gain from giving agents gold tests in ParallACT (oracle 62 to 98, parallel only 16 to 38 on contradictory) indicates the parallel deficit is not explained by under-specified requirements alone.
- In ParallACT, sequential execution recovers nearly all of the oracle's score for open-weight models (60 vs 60 contradictory), so the loss is tied to concurrency, not to splitting requirements across agents.

### Gaps
- No matched equal-token single-agent vs team result on a purpose-built multi-agent coding benchmark was found.
- MLAgentBench with multi-agent systems: no source found. MLE-bench multi-agent numbers are from system papers' snippets, not the benchmark's leaderboard.
- OpenHands delegation: the OpenHands paper describes delegation to a BrowsingAgent, but no delegation-specific SWE-bench result was found. — [arXiv 2407.16741](https://arxiv.org/html/2407.16741v3)
- Agentless as a single-agent contrast, SWE-Lancer manager tasks, HULA, and RepoBench-style multi-agent variants were not researched to a citable level.
- SwarmBench results, "When More Is Less" numbers, and SRDD/SoftwareDev/DevBench/MAGIS/CodeR details need the full papers; items marked "snippet only" should be checked before quoting.
- Model names such as Claude Opus 4.8, Opus 5.5, GPT-6-Astra and GPT 5.6 Sol are reported exactly as the fetched pages gave them and were not independently confirmed.
